# Screenshots — how each image was produced

Both images exist to show **real behaviour**, not to look polished. This file
states the provenance of each so a reader can judge it.

---

## `assets/screenshot-approval.png` (1180×660)

**What it shows:** the approval prompt for `git push --force origin main`.

**Provenance: representation, not a live UI capture.**

The *content* is real — it is produced by the package's own classifier:

```
reason:            destructive git operation
class:             git
sessionScoped:     true
title:             NIBVOK AI Security — action approval
severity:          warning
timeoutMs:         600000
allowedDecisions:  ["allow-once", "allow-always", "deny"]
```

Those strings were generated by calling `classifyToolCall()` /
`confirmClass()` / `SESSION_TRUSTABLE_CLASSES` from this package's
`classifier.js` — the same functions the hook calls at runtime. Nothing in the
text is invented.

The **visual shell is a representation.** OpenClaw renders the approval dialog
in its own Control UI with its own chrome; this image does not capture that. It
re-draws the prompt's real fields in a neutral dialog so the *decision and its
scope* are legible.

**If a true Control UI capture is required for the listing, it needs a live
pending approval, which requires the operator present to trigger it.**

---

## `assets/screenshot-audit-log.png` (1180×340)

**What it shows:** four entries from the live audit log.

**Provenance: genuine data.** Every line is taken verbatim from
`governance-audit.log` on the running host — timestamps, action, reason, and
decision are unedited. Only presentation is applied (column layout, colour, and
newlines collapsed to `⏎`).

The four entries are a real decision lifecycle, in order:

| action | what it records |
|---|---|
| `deny` | a call refused outright, with the reason |
| `confirm` | a call held for human approval |
| `resolution` | what the human decided |
| `session-trust-grant` | the scope approved for the rest of the session |

The log file itself is append-only JSON Lines. It is **not tamper-evident** —
there is no hash chain and no retention policy (see `LISTING.md`).

## Regenerating

Both images are reproducible from the repository:

- the log image re-renders from `governance-audit.log`
- the dialog image re-renders from `classifier.js` decision output

Neither uses mock or placeholder data.
